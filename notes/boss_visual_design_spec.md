# 보스 비주얼 디자인 개선 기획서

**문서 버전**: v1.0  
**작성일**: 2026-04-28  
**대상 파일**: `BossVisuals.js`, `BossSystem.js`  
**작성 목적**: 5개 보스 캐릭터의 시각적 개성 강화 및 전투 몰입감 향상

---

## 1. 개선 배경 및 목표

### 1.1 현재 문제점

현재 모든 보스는 `BossVisuals.buildFrame()` 단일 함수로 외관이 생성되어, **색상 외에 실루엣 차이가 없음**.

| 항목 | 현재 상태 | 문제 |
|------|-----------|------|
| 실루엣 | 모든 보스 동일한 원형 | 보스 진입 시 긴장감 부족 |
| 페이즈 변화 | 색상 틴트만 변경 | 전투 전환점 체감 미약 |
| 보스별 개성 | glowColor 차이만 존재 | 보스 식별성 낮음 |
| 장식 요소 | 스포크 + 링 고정 | 단조로운 반복감 |

### 1.2 개선 목표

- 보스별 **고유 실루엣**으로 첫눈에 식별 가능하게
- 페이즈 전환 시 **형태 변화**로 위기감 연출
- 전투 상태(공격/회복/이동)에 따른 **실시간 비주얼 피드백** 강화
- 기존 `BossVisuals.buildFrame()` 구조를 **유지하면서** 레이어 방식으로 확장

---

## 2. 공통 비주얼 시스템 개선

### 2.1 레이어 구조 재정의

기존 단일 프레임 구조에 **실루엣 레이어**와 **상태 레이어**를 추가.

```
root (PIXI.Container)
 ├─ aura          (글로우 원)
 ├─ halo          (외곽 링)
 ├─ spokes        (스포크)
 ├─ shell         (본체 원)
 ├─ [NEW] silhouette   (보스 전용 실루엣)
 ├─ ring          (내부 링)
 ├─ core          (코어)
 ├─ [NEW] stateLayer   (상태 반응 레이어)
 ├─ [NEW] orbitContainer (궤도 오브)
 └─ valueText     (HP 숫자)
```

### 2.2 공통 추가 함수 (`BossVisuals.js`)

#### `buildOrbitOrbs(radius, color, count)`
보스 주변을 공전하는 오브 컨테이너 생성. `updateBoss`에서 `rotation`만 증가시켜 사용.

```js
// 사용 예시
boss.orbitOrbs = BossVisuals.buildOrbitOrbs(def.radius, 0x79ffbf, 3);
boss.spr.addChild(boss.orbitOrbs);

// updateBoss 안에서
boss.orbitOrbs.rotation += dt * 0.025;
```

#### `buildSpikeRing(radius, color, count, spikeLength)`
페이즈 2 진입 시 스파이크 링 생성. 보스 원 바깥에 날카로운 돌기 추가.

#### `buildPolygonSilhouette(radius, sides, color, jagged)`
보스 본체 위에 올라가는 다각형 실루엣. `jagged: true`이면 홀수 꼭짓점을 안쪽으로 당겨 별 모양 생성.

## 3. 보스별 비주얼 개선 상세 명세

---

### 3.1 Basic Boss (기본 보스)

**컨셉**: *눈에 띄는 정석. 처음 마주치는 보스답게 명확하고 위협적.*

#### 현재
- 원형 프레임, 녹색 글로우
- 페이즈 2: 색상만 붉게 틴트

#### 개선안

| 요소 | 페이즈 1 | 페이즈 2 |
|------|---------|---------|
| 실루엣 | 8각형 외곽선 (원 위에 겹침) | 8각형 + 날카로운 스파이크 링 12개 |
| 코어 장식 | 회전하는 십자 내부 링 | 역방향 회전 추가 (이중 회전) |
| 궤도 오브 | 없음 | 작은 오브 3개 공전 추가 |
| 색상 전환 | 0x79ffbf (초록) | 0xff9b8d (붉은), 스파이크는 흰색 |
| 페이즈 연출 | — | 스파이크 링이 펼쳐지는 0.5초 애니메이션 |

**구현 포인트**
- `boss.phase2Ring`은 이미 존재 → `drawCircle` 대신 `buildSpikeRing()`으로 교체
- 페이즈 진입 시 스파이크 `scaleY` 0 → 1 트윈으로 펼침 연출

---

### 3.2 Advanced Boss (어드밴스드 보스)

**컨셉**: *예측 불가. 텔레포트와 다중 패턴을 쓰는 보스답게 불안정하고 신비로운 느낌.*

#### 개선안

| 요소 | 페이즈 1 | 페이즈 2 |
|------|---------|---------|
| 실루엣 | 삼각형 2개 겹침 (다윗의 별 형태) | 삼각형 3개 겹침 + 빠른 회전 |
| 링 | 단일 링 | 반대 방향 회전 이중 링 |
| 텔레포트 연출 | 단순 순간이동 | 잔상(after-image) 3프레임 남김 |
| 궤도 오브 | 삼각형 꼭짓점 위치에 3개 | 6개로 증가, 속도 1.5배 |
| 불안정 효과 | 없음 | 코어가 0.95~1.05 사이 랜덤 흔들림 |

**구현 포인트**
- 텔레포트 직전 `boss.core.alpha`를 깜빡이는 트윈 추가 (`teleportBlast` 함수 내)
- 잔상: 텔레포트 시 현재 위치에 `alpha: 0.3` 복사본 스프라이트를 30프레임 유지 후 제거

---

### 3.3 Knight Boss (나이트 보스)

**컨셉**: *중세 기사. 직선적이고 묵직한 위압감. 검을 들고 돌진하는 느낌.*

#### 개선안

| 요소 | 페이즈 1 | 페이즈 2 |
|------|---------|---------|
| 실루엣 | 방패 형태 다각형 (상단 평평, 하단 뾰족) | 방패 + 외곽 가시 8개 |
| 블레이드 | 현재 선 기반 → 면 기반으로 교체 | 블레이드 길이 +20%, 잔광 추가 |
| 상태 반응 | CHARGE 시 코어 앞쪽 집중 | ATTACK 시 전신 섬광 1프레임 |
| 이동 궤적 | 없음 | APPROACH 상태에서 발자국 파티클 |
| 색상 | 0x9a7dff (보라) | 0xff8be4 (핑크), 블레이드는 흰색 |

**구현 포인트**
- `drawBlade()`의 `lineStyle` → `beginFill`로 교체해 면 기반 검 형태 구현
- 검 폭: 기저부 10px, 끝부분 3px 삼각형 폴리곤
- ATTACK 상태 진입 첫 프레임: `boss.spr.filters`에 `ColorMatrixFilter` 순간 적용 후 제거

---

### 3.4 Split Boss (스플릿 보스)

**컨셉**: *분열. 하나에서 둘로 쪼개지는 충격. 두 자식은 역할이 달라야 한다.*

#### 개선안

**페이즈 1 (합체 상태)**

| 요소 | 내용 |
|------|------|
| 실루엣 | 원 안에 수직으로 나뉜 반원 2개 (파랑/빨강) — 분열 예고 |
| 내부 장식 | 중앙에 균열선 (얇은 흰 선) |
| 분열 연출 | HP 50% 도달 시 균열선이 넓어지며 분리 — 0.8초 애니메이션 |

**페이즈 2 (분리 상태)**

| 자식 | 실루엣 | 비주얼 특징 |
|------|--------|------------|
| Blue (사수) | 원형 유지 | 내부 십자 링이 빠르게 회전, 사격 시 총구 섬광 |
| Red (돌격) | 삼각형/화살촉 형태 | 이동 방향으로 앞이 뾰족, CHARGE 시 앞에 붉은 오라 |

**구현 포인트**
- 균열 애니메이션: `boss.core` 위에 반투명 흰 직사각형을 `scaleX` 0 → 8로 트윈
- Red child의 실루엣 방향: `child.frame.rotation = child.lockAngle`으로 항상 진행 방향 유지

---

### 3.5 Summoner Boss (소환사 보스)

**컨셉**: *군주. 자신은 뒤에 숨고 미니언을 조종. 위엄 있고 신비로운 느낌.*

#### 개선안

| 요소 | 페이즈 1 | 페이즈 2 |
|------|---------|---------|
| 실루엣 | 오각형 (별 모양) | 오각형 + 외곽 오각 링 |
| 코어 상태 | 미니언 생존 시 `alpha 0.58` (현재) + 보호막 링 | 보호막 링이 두꺼워지고 반짝임 |
| 미니언 생성 연출 | 단순 팝업 | 소환진 원 → 미니언 출현 0.4초 애니메이션 |
| 소환진 | 없음 | 소환 위치에 오각형 룬 마법진 그려졌다 사라짐 |
| 처치 시 | 현재 펄스만 | 미니언 전부 동시 폭발 후 보스 코어 붕괴 연출 |

**구현 포인트**
- 보호막 링: `boss.shieldRing = new PIXI.Graphics()` — 미니언 수에 비례해 투명도 변경
- 소환진: `createMinion()` 호출 시 해당 위치에 오각형 `Graphics` 오브젝트 생성, 60프레임 후 `destroy()`

## 4. 상태별 비주얼 피드백 공통 규칙

전투 상태에 따라 보스가 시각적으로 반응해야 플레이어가 패턴을 직관적으로 읽을 수 있음.

| 상태 | 비주얼 처리 |
|------|------------|
| IDLE / 이동 | 기본 펄스 스케일 애니메이션 (현재 유지) |
| 공격 예고 (Telegraph) | 코어 밝기 +30%, 궤도 오브 가속 |
| 공격 실행 | 1~2프레임 순간 섬광 (흰색 필터) |
| 피격 | 현재 `hitT` 활용 → 코어 흰색 플래시 (유지) |
| 회복 / RECOVERY | 코어 `alpha` 감소 + 느린 후퇴 오라 |
| 페이즈 전환 | 전신 섬광 → 형태 변화 애니메이션 → 재등장 |

## 6. 구현 시 주의사항

- **드로우콜 최소화**: 장식 `Graphics` 오브젝트는 상태 변화 시에만 `clear()` + 재드로우. 매 프레임 전체 재드로우 금지.
- **`buildFrame()` 시그니처 유지**: 기존 호출부 수정 없이 레이어 추가 방식으로만 확장.
- **페이즈 전환 애니메이션 중 무적 처리**: 연출 중 `boss.invincible = true` 플래그 추가 권장.
- **메모리 해제**: 페이즈 전환 후 불필요해진 `Graphics` 오브젝트는 `parent.removeChild()` + `destroy()` 호출.
- **모바일 고려**: 필터(`GlowFilter`) 중첩은 2개 이하로 제한. 특히 미니언/자식 유닛에는 `useGlow: false` 유지.
