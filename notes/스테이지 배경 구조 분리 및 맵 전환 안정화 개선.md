# 개발 의뢰서: 스테이지 배경 구조 분리 및 맵 전환 안정화 개선

## 1. 작업 목적

현재 `background.js`와 `boot.js`에 스테이지 배경 생성 로직과 초기화 로직이 일부 집중되어 있어, 향후 맵이 많아질 경우 유지보수성이 떨어질 수 있다.

이번 작업의 목적은 다음 세 가지다.

1. `getStageTheme()`를 별도 데이터 파일로 분리
2. `StageManager`를 추가하여 스테이지 전환 책임 분리
3. `removeChildren()` 사용 후 리소스 정리를 위한 `destroy()` 처리 검토

---

## 2. 작업 범위

### 2.1 `getStageTheme()` 분리

현재 `background.js` 내부에 있는 `getStageTheme(stage, w, h)` 로직을 별도 파일로 분리한다.

예상 파일명:

```txt
js/data/stage-background-themes.js
```

또는

```txt
js/render/stage-background-themes.js
```

권장 구조:

```js
window.StageBackgroundThemes = {
  getTheme(stageId, w, h) {
    const themeFactory = STAGE_BACKGROUND_THEME_MAP[stageId] || STAGE_BACKGROUND_THEME_MAP.default;
    return themeFactory(w, h);
  }
};
```

예시:

```js
const STAGE_BACKGROUND_THEME_MAP = {
  1: createStage1Theme,
  2: createStage2Theme,
  3: createStage3Theme,
  default: createStage1Theme
};
```

`BackgroundRenderer.drawBackground()`에서는 직접 `getStageTheme()`를 호출하지 않고, 아래처럼 사용하도록 변경한다.

```js
const theme = StageBackgroundThemes.getTheme(stage, w, h);
```

### 2.2 `StageManager` 추가

스테이지 시작, 전환, 환경 초기화, 배경 갱신 책임을 `boot.js`에서 분리한다.

예상 파일명:

```txt
js/systems/stage-manager.js
```

권장 역할:

```js
window.StageManager = (() => {
  function loadStage(stageId, options = {}) {
    // combat object clear
    // environment clear
    // progression stage 설정
    // background redraw
    // atmosphere setup
    // planet setup
    // hazard setup
  }

  function restartStage(options = {}) {
    // 현재 스테이지 재시작
  }

  function getCurrentStageId() {
    return GameState.progression.stage || 1;
  }

  return {
    loadStage,
    restartStage,
    getCurrentStageId
  };
})();
```

`Boot.resetAll()`에서는 모든 스테이지 관련 처리를 직접 수행하지 않고, 가능한 범위에서 `StageManager.loadStage()`를 호출하도록 정리한다.

예시:

```js
StageManager.loadStage(S.progression.stage, {
  resetPlayer: true,
  clearCombat: true,
  clearEnvironment: true
});
```

### 2.3 `removeChildren()` 후 `destroy()` 처리 검토

현재 배경 재생성 시 `S.bg.removeChildren()`만 사용하고 있다.

개선 방향:

```js
for (const child of S.bg.removeChildren()) {
  child.destroy({
    children: true,
    texture: false,
    baseTexture: false
  });
}
```

주의사항:

이미지 텍스처나 공용 텍스처까지 제거하면 다른 시스템에서 문제가 생길 수 있으므로, 기본적으로는 아래 옵션을 권장한다.

```js
child.destroy({
  children: true,
  texture: false,
  baseTexture: false
});
```

목표는 화면에서 제거된 `Graphics`, `Container`, `Filter` 객체가 계속 누적되지 않도록 하는 것이다.

---

## 3. 구현 시 주의사항

* 기존 스테이지 1, 2, 3의 시각적 결과는 최대한 유지한다.
* 맵 전환 시 이전 맵의 배경/행성/효과가 남지 않아야 한다.
* `PlanetSystem.clear()`, `StageAtmosphere.clear()`와 충돌하지 않도록 정리 순서를 확인한다.
* `BackgroundRenderer`는 “배경 그리기”에 집중하고, 스테이지 전환 판단은 `StageManager`에서 처리한다.
* 향후 `asteroid`, `gasPlanet`, `satellite`, `nebulaBlind`, `magneticStorm` 같은 맵을 쉽게 추가할 수 있어야 한다.

---

## 4. 완료 기준

* `background.js`에서 `getStageTheme()`가 제거되거나 최소화된다.
* 스테이지 배경 테마는 별도 파일에서 관리된다.
* `StageManager`를 통해 스테이지 로드/전환 흐름이 명확해진다.
* 배경 재생성 시 기존 DisplayObject가 안전하게 제거된다.
* 기존 게임 시작, 연습 모드, 스테이지 테스트 모드가 정상 동작한다.
* 리사이즈 후 배경이 깨지거나 중복 생성되지 않는다.
* 맵 전환 후 이전 맵 오브젝트가 남지 않는다.
